# Research Literature Review 分层证据池与相关性门禁优化计划

## 通俗解释：究竟发生了什么

- **一句话说明：** 当前流程已经不会拿低相关论文凑篇数，但仍可能把“评分暂时不高”过早解释成“不值得保留”，使潜在近邻、反例或跨学科证据退出后续视野。
- **生活类比：** 整理医院候诊名单时，分诊分数可以决定谁先看医生，却不应把信息不完整、暂时无法判断的人直接从名单上删除。
- **对应到本问题：** canonical 候选集是完整候诊名单，相关性评分是分诊意见，核心/辅助/watchlist/out-of-scope 是不同去向，正式引用集合只是当前真正进入诊室的人。评分决定优先级和用途，不应决定原始证据是否存在。
- **改变前后：** 现在一篇低于 5 分或缺少摘要的论文可能不进入 `selected_papers.jsonl`，后续只能回查原始评分文件；改进后，每篇 canonical 候选都必须出现在分层证据池中，低分、低置信度或资料不足的记录进入 watchlist 或明确排除层，只有满足引用条件的子集进入正文。

## 专业判断：问题在哪里

### 已确认的当前行为

- `select_references.py` 先用全局 `minimum_score` 过滤，再按证据角色和分数排序；低于阈值的记录不会进入 `selected_papers.jsonl`，即使它被标为直接近邻、反方证据或边界证据。
- 选文阶段目前只生成正式选文、BibTeX 和汇总 rationale，没有覆盖全部候选的逐篇分层决策产物，也没有验证 canonical 候选、评分结果和选文结果能否逐条对账。
- 标准综述模式要求论文先有摘要才能入选，而默认摘要补齐发生在选文之后；因此“高度可疑但暂无摘要”的论文可能没有机会进入补齐队列。
- 代码已经读取 `evidence_role`，但当前 AI 评分提示主要要求总分、子主题、alignment 和 extraction，没有要求稳定输出证据角色、相关性置信度、判断依据或不确定性。
- `selection_rationale.yaml` 能报告合格数量和软目标缺口，但不能回答某一篇论文为什么进入核心、辅助、观察或排除层。
- `pipeline_state.json` 记录 canonical hash 和最终引用数量，但尚未记录全量分层证据池的 schema、hash、覆盖率与各层计数。

### 核心风险

相关性不是单一且完全客观的属性。同一篇论文可能与综述正文只有间接关系，却是判断创新性的重要近邻；也可能因为术语不同、摘要缺失或跨学科表达而被低估。继续把一个数值阈值作为“存在/消失”的边界，会产生不可见的假阴性。

同时，完全取消筛选也不可取：正文上下文和引用数量仍需控制，明显无关记录不能污染论证。因此应把“证据是否保留”和“是否进入正式引用集合”拆成两个决定。

## 要达到什么目标

- Search 提供的每条 canonical 候选都有且只有一个可审计去向，任何分数都不能令记录静默消失。
- 相关性评分只参与分层、排序和升级优先级；正式引用资格由相关性、证据深度、证据角色和任务目的共同决定。
- 低置信度、摘要缺失、身份冲突或可能具有否定作用的论文优先进入 watchlist/待核验队列，而不是直接排除。
- `out_of_scope` 必须有明确、可复核的排除理由；“低于某个分数”本身不能成为唯一理由。
- 标准综述继续只引用达到质量要求的论文；`novelty-check` 则偏向高召回，优先保护直接近邻、反方证据和边界证据。
- 参考篇数继续作为预算与诊断信号，而不是填充命令；候选池规模、核心证据数和正式引用数分别报告。

不在本次处理范围：修改 Search provider、改变 `rls.v1` canonical 去重结果、对全部候选无差别下载全文、以固定学科关键词替代语义判断，或要求正文引用所有保留记录。

## 必须保持的规则

1. **全量保留：** canonical 候选数量必须与分层证据池数量一致，ID 唯一且顺序可回溯。
2. **层级与角色分离：** `core/supporting/watchlist/out_of_scope` 表示处理层级；`direct-neighbor/contradictory/boundary/methodological/supporting` 表示论文在论证中的作用，两者不能混为一个字段。
3. **保留不等于引用：** watchlist 可以影响风险判断和补检索策略，但默认不能支撑正文事实主张；正式引用集合由证据池派生。
4. **不确定不等于无关：** 缺摘要、低置信度、身份冲突或评分依据不足时，不允许仅凭低分进入 `out_of_scope`。
5. **上限只限制引用集合：** `target_refs/max_refs` 控制写作上下文和正式引用数量，不截断完整证据池。
6. **排除也要留痕：** 明确无关的论文仍保留 ID、判断依据、证据深度和排除理由，以便复查。

## 改进方向

### 一、把单一选文结果拆成“完整证据池”和“正式引用集合”

新增覆盖全部 canonical 候选的 `evidence_pool_{主题}.jsonl`。每条记录至少标明层级、相关性判断、判断置信度、证据角色、证据深度、是否可引用、是否需要补摘要/全文，以及可复核理由。现有 `selected_papers_{主题}.jsonl` 保留为兼容接口，但改为从证据池中派生，只包含当前任务真正允许进入正文或查新结论的子集。

`selection_rationale.yaml` 增加 canonical 总数、已评估数、未评估数、各层计数、正式引用数、待升级数、排除原因分布和完整覆盖状态。这样用户看到“最终只引用17篇”时，也能确认其余候选仍在证据池中并知道各自去向。

对普通用户而言：论文可以暂时不进入正文，但不会从地图上消失。

### 二、把相关性从单一分数改成“判断 + 置信度 + 理由”

保留 1–10 分，避免破坏现有输入，但不再让分数独自决定去留。评分提示和数据契约补充：相关性档位、判断置信度、证据角色、不确定性、判断所依据的标题/摘要/全文，以及结构化 reason code。

建议的默认路由是：高相关且证据充分者进入 core；有论证用途但不是主线者进入 supporting；分数临界、低置信度、资料不足或可能构成关键反例者进入 watchlist；只有证据足以确认范围不匹配时才进入 out-of-scope。全局阈值仍可用于排序和候选引用资格，但不得直接删除记录。

需要避免机械规定“某个分数必然属于某层”。不同任务下，同一论文的层级可能不同，尤其是 `novelty-check` 中的直接近邻和反方证据。

对普通用户而言：系统不仅说“这篇是4分”，还要说明“为什么是4分、判断有多可靠、接下来该怎么办”。

### 三、把摘要补齐改成“先分诊、再定向补齐、最后确认引用”

将选文阶段拆成两个概念步骤：先基于现有信息生成初步证据池和升级队列；再只对高价值且信息不足的记录补摘要或全文；最后计算正式引用集合。升级队列优先覆盖直接近邻、反方证据、边界证据、临界分数和低置信度记录，不对全部候选无差别补齐。

标准综述中，只有标题的记录可以保留在 watchlist，但在获得足够内容前保持 `do_not_cite`。`novelty-check` 中，这类记录必须出现在待确认近邻清单，必要时阻止确定性的新颖性结论。

对普通用户而言：资料不全的可疑论文会被安排进一步核查，而不是在核查前被淘汰。

### 四、按任务目的设置不同的“错判成本”

标准综述偏向引用准确：核心和辅助层达到证据要求后才进入 BibTeX 和写作上下文。`novelty-check` 偏向不漏关键近邻：直接近邻、反方和边界角色即使分数临界或只有标题，也应保留并触发升级，但不能在证据不足时被当作已证实结论。

当前代码中“先按最低分过滤、再按角色排序”的顺序应调整为：先完成全量分层，再按 purpose 从各层派生引用或查新集合。角色可以提高复核优先级，但不能凭角色标签绕过证据深度要求。

对普通用户而言：写综述时少引用错文献，查新时少漏掉可能推翻创新性的文献。

### 五、增加覆盖对账、状态记录和恢复门禁

证据池生成时以 Search manifest 和 canonical hash 为依据，逐条核对 ID。评分缺失的记录也必须以 `unassessed/watchlist` 留在证据池，并将流程标记为证据覆盖不足；重复、额外或无法关联的评分记录应 fail-closed。

`pipeline_state.json` 记录证据池路径、schema、hash、canonical 覆盖率、分层计数、引用集合 hash 和选择策略摘要。resume 时，如果 canonical 输入、评分输入、purpose、阈值或分层策略发生变化，应从分层阶段重算，不能沿用旧的 `selected_papers`。

对普通用户而言：中途恢复任务时，不会拿旧筛选结果配新的候选库或新规则。

### 六、保留兼容接口并明确发布边界

继续生成 `selected_papers.jsonl`、`references.bib` 和 `selection_rationale.yaml`，避免破坏写作、校验和旧调用方；新增证据池 schema 时升级 Skill 次版本，并只在 `config.yaml` 维护版本号。旧运行缺少证据池时允许只读查看，但不得伪装成已经完成全量分层的新运行。

完整证据池默认属于内部审计产物；`novelty-check` 应把分层摘要、关键 watchlist 和未确认近邻作为正式结果的一部分。标准综述只有用户显式要求 supporting/audit 输出时才发布完整池，避免把大体积中间数据混入 PDF/Word 交付目录。

## 实施范围与顺序

1. 先固定分层证据池、正式引用集合和 selection rationale 的语义与兼容边界，并同步评分提示需要输出的字段。
2. 将选文逻辑改为“canonical 全量对账 → 初步分层 → 定向补齐队列 → 最终引用派生”，消除先过滤后补摘要的顺序问题。
3. 在 pipeline state 中接入证据池、覆盖率、hash、purpose 和策略指纹，调整 resume 与后续写作/校验只消费正式引用集合。
4. 更新 Skill、配置、README、CHANGELOG 和回归测试；实施前重新核对 `huangwb8/skills` 的现行项目规范。

主要受影响范围预计包括评分提示、`select_references.py`、`pipeline_runner.py`、配置中的 selection/abstract-enrichment 语义，以及 Review 的定向测试。Search 的 canonical 生产逻辑和 Radar 的独立 landscape 契约保持不变。

## 如何确认完成

| 场景 | 预期结果 |
|---|---|
| 65篇高相关、50篇低分 | 正式引用集合最多包含65篇合格文献；证据池仍有115条，50条各有明确层级和理由 |
| 只有17篇可引用 | 流程可交付17篇并报告软目标缺口；完整池数量不受17篇限制 |
| 4分的直接近邻或反方证据 | 不因低于全局阈值消失；至少进入 watchlist，并按 purpose 决定是否升级核验 |
| 高分但无摘要 | 不直接进入标准正文引用；保留并进入定向摘要补齐队列 |
| 只有标题的潜在强近邻 | 标记 `do_not_cite` 和待核验；novelty-check 不得据此作确定性新颖性结论 |
| 低置信度或身份冲突 | 不允许直接进入 out-of-scope；保留不确定性和后续动作 |
| 明确范围不匹配 | 可进入 out-of-scope，但仍保留 ID、证据深度和排除理由 |
| AI 漏评一条 canonical 候选 | 证据池仍保留该条并标为 unassessed；覆盖门禁报告不足，不得显示 coverage complete |
| canonical、评分或策略在 resume 前变化 | 旧选择结果失效，从分层阶段重新计算 |

自动化验证至少覆盖：canonical ID/数量/顺序对账；层级枚举和逐条理由；低分关键角色不丢失；标准与 novelty-check 的不同引用资格；定向补齐队列；缺失评分；策略漂移恢复；现有 BibTeX、写作和引用数量校验的兼容性。

## 风险与待确认事项

- 分层仍包含语义判断，不能把新字段变成另一套伪精确分数。验收重点应是可解释、可复查和不静默丢失，而不是要求不同模型每次给出完全相同层级。
- 全量证据池会增加存储和上下文成本。实现应保存结构化决策账，写作阶段只加载正式引用集合或按需读取 watchlist，不能把全部候选重新塞入写作上下文。
- “明确无关”的证据标准需要在评分提示中给出通用 reason code，但不能硬编码某个学科的关键词规则。
- 低分关键角色可能来自错误的角色标注，因此它应触发复核，不应自动晋升为可引用核心证据。
- 当前 Radar 已有相似的四层 landscape。实施时应对齐层级词义和基础字段，但避免让 Review 直接依赖 Radar；两者都应能独立消费 Search canonical bundle。
