# bac-v13：BSK 通用门禁与状态一致性优化计划

## 通俗解释：究竟发生了什么

- **一句话说明：** BSK 像一个只在“办理转移手续”时查票的闸机，乘客如果从旁边的工作人员通道直接进入下一站，闸机不会知道。
- **具体场景：** BSK 在收到 `state transition` 时能够检查 Verifier 和 Gate，但不会拦截任意 Skill 的文件写入或业务调用；因此 v13 没有 Gate 失败，而是没有触发 BSK。
- **对应到本问题：** State/事件日志是通用控制面，`research-idea` 的候选和查新字段属于领域数据，不应硬编码进 Kernel。
- **改变前后：** 当前 BSK 只认证主动提交的转移；改进后，受保护的阶段动作还必须取得通用 action authorization/handoff，且旧事件不能跨状态复用。

## 专业判断：问题在哪里

- Kernel 的现有机械逻辑在被调用时正常：非法边、缺 required Verifier 或不允许的 Gate 会被拒绝。
- 通用缺口有两层：一是缺少可供业务入口调用的“当前 State 是否允许该动作”授权接口；二是 State invariant 的证据窗口必须严格从当前 State 最近一次进入事件开始。
- BSK 不应扫描所有外部文件，也不应认识 `research-idea`、Premium 或 synthetic review 等领域概念；领域入口由 Skill 调用通用授权接口。

## 要达到什么目标

- 提供可复用的、fail-closed 的阶段动作授权能力，避免“只要不调用 transition 就没人拦截”。
- 保证 Verifier、Gate、handoff 和 transition 只能使用当前 State、当前 `run_id/attempt_id` 和当前证据窗口内的事件。
- 支持追加式事件、重放、并发冲突、失败恢复和版本兼容；不破坏现有合法状态图。

不在本次范围内：把科研质量规则写进 Kernel、实现 `research-idea` 专用 Verifier、扫描任意项目文件，或替换 BAC 账本。

## 改进方向

### 方向一：增加通用 action preflight/授权契约

在 BSK 提供领域无关的接口：调用者提交当前 State、目标动作、`run_id/attempt_id`、handoff 和证据摘要，Kernel 返回允许/拒绝及原因。授权必须绑定当前快照和状态版本，并在实际动作前可验证；没有授权时默认拒绝受保护动作。

对普通用户的变化：下游工具不能只因为绕过了状态转移命令就继续工作。

### 方向二：收紧 State/Verifier/Gate 的时间窗口

状态离开时只接受当前 State 最近一次进入事件之后产生的、身份匹配的 Verifier result、Gate 和 handoff。旧 State 的通过结果、同一 attempt 的过期结果和跨阶段复用结果均拒绝。重放与实时执行必须得到相同结论。

对普通用户的变化：以前做过的一次通过不能被拿来追认后来才产生的材料。

### 方向三：强化并发、失败和版本边界

事件追加使用锁和单调序列；授权消费具备幂等键；中断后只能恢复同一 attempt 或显式创建新 attempt。Pack/State/Verifier 版本和 alias 按索引解析，协议不匹配时明确失败，不降级为字符串状态。

对普通用户的变化：并发续跑或工具崩溃不会悄悄制造第二条互相矛盾的状态链。

### 方向四：提供可观测的拒绝证据

每次拒绝记录原因码、当前 State、期望动作、相关事件序列和恢复建议；`status/rebuild` 只重建投影，不把缺失的业务事件补成真实执行。

## 实施范围与顺序

1. 先冻结通用接口和不变量：授权对象、事件字段、证据窗口、幂等键和拒绝原因。
2. 实现 State-entry window、过期结果拒绝和实时/重放一致性检查。
3. 实现 action preflight/authorization，并让现有 Skill host 能调用；保持旧 transition API 的兼容行为。
4. 补充并发、崩溃恢复、版本不匹配和事件篡改测试，再更新 Kernel 文档与版本记录。

## 如何确认完成

- 缺 Gate、缺 required Verifier、错误边、错身份、旧窗口结果和过期 handoff 均 fail-closed。
- 处于某 State 时，未经授权的受保护动作无法取得成功授权；授权后动作记录与其 State/attempt 一致。
- v12 事后回填 fixture 在实时检查和重放检查中都失败；正常 fixture 的实时和重放结果一致。
- `status/rebuild` 不新增伪造的业务事件；事件序列、哈希链和并发锁回归通过。
- Kernel 测试不包含 `research-idea` 领域 ID/字段，证明实现仍是通用能力；安装、协议兼容和 BAC verify 通过。

## 技术补充（按需阅读）

- 建议把授权视为短生命周期的 handoff/capability，而不是新增领域 State；动作名称保持调用者提供的通用字符串或注册契约，Kernel 只检查状态和身份绑定。
- 事件至少保留 `event_id`、`seq`、`run_id`、`attempt_id`、`state_before/state_after`、`handoff_id`、`evidence_refs`、时间和哈希。
- 任何“自动根据文件存在推进状态”的实现都不在范围内，因为它会重新引入不可审计的隐式控制路径。

## 风险与待确认事项

- 新授权接口会影响所有使用 BSK 的 Skill host，需要先盘点调用者并提供清晰的协议版本错误。
- fail-closed 可能暴露宿主本身的越权写入；Kernel 不能替代操作系统权限，必须在文档中明确边界。
- 旧运行现场只能只读重放；不允许为了让历史任务通过而修改事件日志。
