# research-idea 研究脉络摘要叙事优化计划

## 通俗解释：究竟发生了什么

现在的“研究脉络 map 摘要”经常先给读者一张研究分类表，再列出研究机会。对熟悉领域的人，这像一份好用的索引；第一次接触该领域的研究生却可能不知道分类为何重要，也看不出机会是怎样从已有研究中产生的。以 `v20.md` 为例，开头五条研究线都可追溯，但读者须先理解 PROV、SLSA、过程审计等术语，才有机会理解它们与“人工授权能否被正确审计”的关系。文中的 `R1` 等编号和文末条目也更像工作笔记，缺少统一的学术引文与参考文献格式。

期望的阅读体验是：导师先说明大家试图解决的真实问题，带学生看几条研究路线分别解决了哪部分、在哪些条件下失效，最后解释自己为何认为某个未知值得研究。读者读完正文，就能说清“为什么重要、已经知道什么、为什么仍不知道、哪些证据可能改变判断”；需要核查时仍能沿论文编号回到来源。

## 专业判断：问题在哪里

- **当前现象：** `research-synthesis.md` 要求研究线比较、关系、机会和时间线，`report-template.md` 又要求最终摘要复用这三部分并保留时间线。历史 `v*.md` 因而多采用“表格或年代梳理 → 一段综合判断 → O 编号清单”。`v19.md` 已改用较多叙述，说明形式可以更自然，但从研究发展直接跳到机会的距离仍偏大。模板目前直接用 `[R1](#r1)` 作报告引文，并在 `R1` 条目中混写标题、链接、阅读深度和本轮解释；`validate_report.py` 只核对 R/O 锚点存在及编号匹配，不检查书目信息是否成形。
- **影响：** 论文覆盖和引用可以很完整，关键的概念关系却留给读者自行补足；“缺什么”容易被写成缺一套系统、一个数据集或一次实验，尚未说明它对应哪一个重要的认知未知。
- **判断依据：** 叙事问题主要在写作任务的定义和模板示范；引文问题还涉及报告引用语法及其校验。两者均不需要改检索或 BSK。表格适合存放完整 map，最终摘要应从 map 中选择能支撑论证的关系，写成可独立阅读的介绍。这是对样本的写作诊断，不能仅凭段落形式推断所有历史报告的科学判断有误。

## 要达到什么目标

正式报告的这一节要像熟悉领域的科学家向新入组研究生解释自己的知识地图：读者先理解研究对象和核心术语，再沿证据看见主要答案、研究线之间的关系、最强近邻、有效范围与未解问题，最后理解 O 机会为何值得提出。

改写必须保留可核查性：重要事实就近引用来源，来源结论与本轮跨文献推断分开，全文和摘要级证据各按其深度表述。正式报告采用一种统一的学术引文格式，并以最后一个二级小节 `## References` 集中列出参考文献；工作 map 中稳定的 R 编号仍可回溯到同一条文献，O 编号仍指向稳定的机会。时间线、表格和图按内容需要选择，不设固定段数或字数。

本次不回写 `bensz-auto-contribution/docs/ideas/v*.md` 历史报告，也不改变文献检索、候选查新、审查轮次或 BSK Gate。引文格式可能需要调整报告校验与引用契约；实施时须保留旧报告只读兼容。借鉴 `nsfc-justification-writer` 的“价值和已知证据 → 认知瓶颈 → 科学问题”论证方式，不把它增加为运行依赖，也不套用基金申请书的修辞。

## 改进方向

### 让工作 map 显示科学家脑中的关系

在既有比较表和 O/R 索引之上，明确要求综合研究线之间的关键关系：它们研究的对象和测量是否相同，主张是否互补或竞争，各自依赖什么前提，最强反例是什么，尚缺哪种辨别证据。关系可以按问题组织；只有来源确实支持认识转折时才讲历史演化。工作 map 继续保存 landscape 覆盖、Search record ID、证据深度和限制，供后续候选和核查使用。

这样做的直接效果是，撰写者在压缩摘要前已有可选择的解释路径，而不只是一张按论文分组的目录。

### 把最终摘要写成带读者前进的论证

为报告摘要提供柔性的叙事顺序：

1. 从一个具体问题或需要作出的判断进入，解释研究对象及必要术语。
2. 介绍最相关的研究路线各自想回答什么、用什么证据回答了什么，以及结论成立的条件。
3. 说明路线之间的连接、分歧或测量差异，正面处理已解决最多的近邻和最强反方证据。
4. 把边界转成未知的关系、机制、性质或适用条件，说明回答它会改变什么认识或决策，再引出 O 机会。

这是一条推理路径，不是四段式模板。某些主题适合先讲争议，某些适合先讲一个实验现象；已知研究没有真实争议时应直说。比较表可以帮助读者回看，不能替代叙述中的解释。

### 让文献引用符合统一学术格式

建议中文 Markdown 报告默认采用实施时核对过现行版本的 **GB/T 7714 顺序编码制**；若用户指定目标期刊或学位规范，按其样式输出。正文在相关主张处使用链接到文末条目的数字引注，如 `[1]`。所有报告结论分支均把 `## References` 放在最后：位于“推荐与投入排序”“淘汰理由与重启条件”或“证据缺口与恢复位置”等结尾章节之后；该节只列规范书目，不再接 O 机会、研究备注或其它章节。条目按文献类型提供可核验的作者或机构、题名、出处、年份、卷期页或版本、DOI/稳定 URL 等适用字段。不同文献类型不能靠同一套随意的“标题＋链接＋一句评论”代替。

`R1` 等编号继续作为工作 map、Search record、论文解读和候选依据之间的稳定证据身份；正式报告建立确定的 `R1 ↔ [1]` 映射，读者看到的是学术引注。阅读到全文还是摘要、引用的是哪一节，以及“本轮认为它支持或限制什么”，放在证据说明中，不混进参考文献著录。文献元数据优先复用已核验来源；缺作者、出处、年份等关键字段时标明待核验并收缩相关论断，不臆造完整条目。

为避免显示格式改了却丢失追溯链，实施时须审查模板、报告校验器、候选“脉络依据”字段和完成检查对 R 编号的依赖。按最小兼容方案增加引用样式标记或修订报告契约，使新报告使用规范引文、旧报告保持可读且不冒充新版合格报告；具体契约形式以依赖审查结果确定。

### 增加专业可读性与保真复核

借鉴立项依据 Skill 的语义审查，要求宿主 AI 在成稿后检查：新人能否理解首次出现的概念；每个关键判断能否找到就近证据；段落是否自然推出下一个问题；所谓缺口是否指向重要未知；摘要级证据有无被写成定论。发现长句、抽象名词串或跳步时，只在保留事实、限定和引用的条件下改写。

这项复核保留为 AI 的语义判断。确定性脚本继续负责章节、O/R 锚点和路径等可机械核验的事项，不引入按词频、段数或“用了某句式”判定叙事质量的硬门槛。

## 如何确认完成

- **新人阅读检查：** 不依赖候选评估章节，读者仅凭 map 摘要能复述研究对象、已有答案、最强近邻、关键边界，以及 O1 从哪里来；核心术语首次出现时有足够解释。
- **科学论证检查：** 至少一条研究线之间的关系被解释清楚；缺口表述为能被证据区分的重要未知；没有把发表先后当作继承、测量差异当作矛盾，或把“未检出论文”当作新颖性证明。
- **证据保真检查：** 样稿逐项对照原报告与工作 map，确认关键事实、限定、反方证据、证据深度、R/O 对应关系未丢失或夸大；不能核验的跨文献综合明确标成判断。
- **引用格式检查：** `## References` 是报告最后一个二级小节，在每种结论分支中位置一致；正文、候选依据与该节使用同一种引文样式。每个引注都能定位到唯一条目，每个条目都能回到原 R 身份与稳定来源；书目字段符合选定标准，阅读深度和本轮评论不混入著录。对缺失元数据给出明确待核验提示，不补造作者或出版信息。
- **兼容性检查：** 新报告的引用格式校验通过；旧版 R 锚点报告仍可读取，但不能凭旧格式通过新版引用门槛；现有 O/R、候选和完成检查相关回归保持通过。
- **工程检查：** 运行现有报告结构校验、Skill 文档检查和与改动范围匹配的回归；核对历史报告没有被修改，Git 差异仅包含计划批准后的 Skill、文档、版本与记录文件。

## 风险与待确认事项

- “深入浅出”若被理解为删去专业限定，会让结论变得更顺口却更不准确。验收优先保留对象、条件、证据强度和反例，再改善阅读顺序。
- 某些主题没有公认的单线历史或研究阵营；指南只要求解释真实关系，不强制时间线、冲突或固定段数。
- 最终摘要可以比目前更长，但要以推理所需的信息为准，避免复制工作 map 的完整文献目录。若样稿显示长度与可读性冲突，优先删重复罗列，保留决定性证据与边界。
- 数字引注是建议的中文默认样式，并非所有学科或目标期刊的唯一规范；用户指定作者—年份制等样式时应覆盖默认值。格式转换不得改变 R 身份、引用对象或证据深度；是否需要新的报告契约版本，须依据校验器与完成检查的实际依赖决定。
