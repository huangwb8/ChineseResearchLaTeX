# 文献综述质量退化调查与修复计划

## 问题判断

一份综述能编译、引文编号齐全，并不意味着它已经成为可信、好读、可继续修改的研究文稿。目前流水线把这些不同层次的要求混在一起：正文与版式依赖执行者临场决定，而脚本在完成少量检查后就给出过宽的“通过”结论。改进后，用户应得到稳定的学术版式、能够回溯的关键论断，以及带源文件和真实检查范围的交付包。

本次以“低位／超低位直肠临床诊疗的研究进展-01”为主例，抽查另外五份历史综述，并追溯当前 `research-literature-review` 的源码和 Git 历史。用户的质量担忧成立，但“所有旧稿都比新稿可靠”不受证据支持：旧稿也有引文错配、Word 标题层级错误和缺乏原始证据的问题。应恢复有效的能力和质量保障，而不是整体回滚。

新实例并非“缺交付文件”：它已有 PDF、Word、Markdown、TeX、Bib、BST、图表、工作条件、验证说明和校验文件。这些是执行时补齐的能力，当前发布脚本并不能稳定重现同等交付。该实例使用自写导言区，不能把封面和字体设计直接归因于内置模板。

## 根因与修改方向

### P0：让验证结论与真实检查范围一致

`pipeline_runner.py:run_stage_6_validate` 仅用字数和 TeX 检查决定是否通过；子主题检查失败只打印提醒，预算失败被忽略，报告生成失败也不阻断。`generate_validation_report.py` 用任意“✓”或“passed”判断成功，缺少章节信息时反向补出“存在”，甚至提供 `--force-pass`。`validate_review_tex.py` 把展望与结论合并，而且允许正文中的关键词代替真实标题。

修改现有脚本，使必需检查的失败传递到阶段结果；分别核对摘要、引言、主体、讨论、展望和结论，排除注释中的假引用。报告明确区分结构、摘要可用性、语义证据核验、导出与目视检查，未经执行的检查保持“未验证”。不引入新的状态机、Verifier Pack、签名或完成认证协议。

验收：缺结论、注释伪造章节、报告生成失败、摘要数据损坏、子主题不合规均不能获得阶段通过；已有失败输出中夹有成功字符也不能被报告解释为通过。

### P0：把关键证据带到写作阶段

当前证据卡截断摘要到 800 字符，并丢弃评分阶段已有的 extraction、alignment、证据角色等信息。随机试验的主要结果与限制常在摘要后半段，单纯保留前缀会损失决定结论所需的信息。评分分布比例和参考文献数量不能补偿这个缺口。

默认保留完整摘要，并保留已有结构化提取、来源身份、证据深度和边界；显式截断时给出截断状态及原始记录定位。写作要求以问题和研究脉络组织，关键定量主张核对人群、设计、分母、终点、随访、效应与不确定性。主题覆盖、经典原始研究、阴性结果、长期更新和指南分歧由 AI 判断，脚本不假装理解临床证据。

验收：包含摘要后段结局的测试记录不会静默丢失；已有人工/AI 提取字段完整传递。保留“不凑篇数”的相关性阈值，证据不足时补检或收窄结论，不能编造结果填配额。

### P1：恢复可以实际调用的学术版式

当前 `latex.template_path` 指向 Pandoc 模板，但 PDF 编译器只把其目录加入搜索路径，不会将版式应用到 `review.tex`。因此配置看似存在，稿件仍完全依赖执行者自写导言区。Word 又默认把标题下移两级，且没有固定数字引文样式。

新增轻量、可直接渲染的论文模板入口：默认标题、摘要和正文连续排版，统一自动编号、中文字体回退、数值引文和表格宽度计算。旧 Pandoc 模板保留兼容；自定义完整 TeX 不被强行重写。封面、目录、营销档位标签与任务编号不自动进入正文；用户明确要求的题名原样尊重。Word 从 Heading1 开始，采用明确的数字引文样式。

验收：同一短篇测试稿实际编译 PDF 和 Word；Word 一级/二级标题、表格、图片和引文存在；中文无缺字。PDF 未解析引文、缺字等编译告警不能被“退出码 0”掩盖；失败日志保留，目视检查仍需真实执行。

### P1：交付可复现的文稿包

提交 `1cfa185` 引入发布白名单后，默认只交 PDF/Word，源文件和验证说明成为可选项；同时白名单不接受图表目录和 BST。发布器还允许仅有一个 PDF 的不完整产物成功发布。这与“可编辑、可复核”的研究交付目标不一致。

标准运行默认交付 PDF、Word、TeX、Bib、工作条件、验证报告，并沿 TeX 的显式相对引用带齐图表、输入片段与 BST。只收集实际依赖，阻止越界路径、符号链接逃逸和同名覆盖。提供显式仅阅读文件选项，保留既有自动化的轻量用法。过程日志、候选池、预算和缓存仍留在任务工作区。

验收：缺 Word、缺必需支持文件、缺图、越界依赖和发布冲突在写入目标前失败；一个完整示例发布后，可从独立目录用常规 TeX 工具重新编译。

### P1：恢复写作契约的判断价值

提交 `1b115f6` 将该 skill 的相关说明合计压缩了数千行。压缩本身不是错误，但研究类型、样本量、定量结果、事实保护与具体示例被削弱；部分旧规则本身也不应恢复，例如机械追求引用分布比例、把所有研究方法描述都当成流程泄露。

重写精简而具体的写作指南：区分叙述性综述与正式系统综述；前者以研究问题组织，后者保留必要方法、筛选与偏倚评价。一个小节应回答问题、比较证据并作出有边界的判断，避免每项研究后反复插入相同免责句。讨论解释分歧，展望提出可验证问题，结论回收已有论证。给出同一证据的差/好写法示例。

验收：规范能解释新实例为何需要减少碎片化和重复限定，也能拒绝旧稿中“无显著差异即等效”、整体队列冒充亚组、指南版本混用等写法；不以数量阈值认证内容质量。

## 实施顺序与范围

1. 固定只读样本和当前源码基线，保存可复核统计及最小失败反例。
2. 修复验证结果传递、报告措辞与证据卡信息丢失。
3. 接通模板和 Word 样式，完善编译诊断，再恢复完整交付包。
4. 同步 SKILL、README、配置、开发验证指南、变更记录和 BAC；运行既有定向回归与真实导出/独立重编译。

本轮修改限于 ChineseResearchLaTeX 中的目标 skill、相关测试和维护文档。六份真实样本保持只读，不安装系统级副本、不发布远程版本、不重新生成整篇临床综述。历史运行保持显式兼容；新增更严格的交付检查可能暴露旧产物缺失，不能自动补造通过记录。

## 验收与边界

自动化验收覆盖真假通过、证据字段保持、格式转换、完整发布、依赖与路径安全、恢复兼容。真实样本用于外观与内容反例，不作为未经独立核查的标准答案。测试应包含成功和失败两类，不能仅比较生成文件是否存在。

长篇内容改善属于后续真实任务的效果验收：用相同题目、相同文献池与同一预算比较论证密度、引文适切性、图表用途和重复限定，必要时做盲评。本轮工程回归通过只能证明已修复的机制有效，不能宣称已经证明未来所有长篇综述都优于旧版。

本次读取了上游 skills 规范及 BSK 公开接口；采用现有领域脚本修复，不启用 verifier-state-architect，不新增通用运行基础设施。reviews 项目的原 BAC 账本存在既有 root_hash 错误，保持原状；维护证据记录到源码仓库的既有账本并保留原有 warning。
