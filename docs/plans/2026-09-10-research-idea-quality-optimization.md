# research-idea 科研选题质量优化计划

日期：2026-09-10。状态：待实施。本轮只制定计划，未修改 Skill、脚本、配置或原研究报告。

## 通俗解释：究竟要改善什么

这次研究建议花了很多精力说明“什么话不能说得太满”，却没有充分回答“这个问题为什么值得研究”。读者得到了一份谨慎、具体的实验起步建议，但很难感受到它能带来什么重要的新认识。

以 BAC 案例为例：现有流程推荐先研究“日志写着测试通过，是否就能证明交付版本被测过”，主要理由是贴近现有代码、容易起步。优化后，应先判断这个问题是否存在尚未解决的实质困难，以及回答它会改变什么认识或决策；再把它与其他方向比较，最后说明近期可以投入到哪一步。若只能支持工程修补，明确作此定位；若暂时找不到足够好的研究题目，也允许给出这个结论。

研究 map 可以理解为一张帮助选择方向的地图。论文名单告诉我们有哪些地点；真正有用的地图还要告诉我们它们怎样相连、哪些道路已经走通、哪里存在争议、绕过哪个障碍最有价值。本次优化要补足这些关系和判断。

## 专业判断：事实与原因

本计划依据实战产物与当前仓库源码制定。单次案例能暴露缺口，不能证明每次运行都会出现同样结果。

| 已核对的现象 | 对优化的含义 |
|---|---|
| 中间 map 共 39 行，以时间顺序的论文介绍和三个缺口为主 | 缺少跨论文综合的可操作标准；增加篇幅或画图本身不能解决问题 |
| 首选 C1 的理由侧重当前工程资产适配 | 应分开判断科学价值、证据可信度和近期投入，而不是由可行性代替价值 |
| 初始候选包含审阅时机与人工预算分配方向，综合时较快移至远期 | 应保留替代方向和淘汰理由，检查共享背景是否过早收窄问题空间 |
| 第二、三轮审查草稿内容相同，后续主要检查表述与一致性 | 多轮审查需要不同的判断任务，并证明有新的评估内容 |
| 查新结果为 uncertain，最终报告也承认全流程未完成 | 不能把本次诊断表述为完成门禁错误放行；需要改善有限建议与正式推荐的表达边界 |
| 结构检查将 C1/C2/C3 标题识别为零个候选 | 存在确定性的标题解析问题，应修复，但不能把格式修复当成科学质量提升 |

当前 Skill 已要求文献调查、map、反证路径和科学重要性评价。主要缺口是这些要求尚不够具体，缺少能区分“形式合格”和“值得研究”的示例与判据。共享 map 导致候选收敛、可行性压倒科学价值是本次证据支持的解释，后续仍需用跨领域样例检验。

此前的[协同进化计划](2026-09-02-research-topic-extractor-research-idea-协同进化优化计划.md)范围较大，包含主题提取、检索和科研网络扩展；本计划先处理 `research-idea` 内部的科研判断。已有[阶段控制计划](2026-09-09-research-idea-verifier-state.md)提供运行基础，本次不重新设计其基础设施。

## 要达到什么目标

完成优化后，用户应能从报告中清楚回答：

- 为什么这个问题值得做，成功后增加什么认识，失败后能排除什么解释。
- 它如何由已有研究的证据、边界或未解释现象推导出来。
- 它与最近研究的差异为什么重要，而不仅是对象、参数或实验组合不同。
- 为什么选择它，最强替代方向是什么，以及资源条件变化时排序是否改变。
- 当前得到的是正式推荐、没有合格候选的评估结论，还是证据不足的阶段性建议。

保留证据诚实、全文阅读边界、强基线和可证伪性。研究价值可以来自机制解释、重要的经验发现、测量改进、可靠复现、方法进步或决策改善；不要求每个题目宏大、反直觉或具有复杂算法。

本次规划不扩展触发范围，不开发完整实验方案，不重构相邻 Skill，不建设通用知识图谱平台，不新增 Agent 数量、默认查新档位或基础设施依赖。实施阶段仅在已有接口确实无法承接目标行为时记录依赖缺口，不顺带扩大范围。

## 改进方向

### 先明确研究目标，再分别判断价值与投入

在读取用户资料时增加一份简短的研究目标说明：用户想获得哪类研究贡献、服务什么问题或决策、有哪些已经确认的资源与时间约束。资源区分“已具备”“明确没有”“尚不清楚”；源码里没有某项能力，不能直接推断团队没有能力建设它。

资料未说明研究目标时，先给出合理解释和不确定性。只有目标差异会改变主线选择时才澄清，避免把每次任务变成调查问卷。

比较候选时分开回答三个问题：

| 判断 | 核心依据 | 输出方式 |
|---|---|---|
| 科学价值 | 未解决问题的重要性、预期知识增量、可区分的解释或可改变的决策 | 有理由的优先级，保留并列与分歧 |
| 判断可信度 | 关键证据深度、最近工作覆盖、未知条件 | 明确哪些结论稳健、哪些暂定 |
| 近期投入 | 已确认的资源、成本、验证路径和失败代价 | 下一步值得投入多少，以及资源变化后的选择 |

不设置一个可用高可行性抵消低科学价值的加权总分。低价值但容易做的项目可以进入工程建议，不能自动成为首选科研方向。高价值而当前条件不足的候选保留条件性定位，不被默默删除。

### 将研究 map 改为跨论文的解释与证据地图

保留时间线，但把主体改成“研究问题如何演化、不同解释如何竞争、证据在哪些条件下有效”。复用逐篇解读结果，由主 Agent 做一次跨论文综合；发现关键材料不足时定向补读，不直接用常识补齐关系。

最小 map 由三部分组成，优先用 Markdown 表格和必要的 Mermaid 图，不先建设独立图数据库：

| 部分 | 需要表达什么 |
|---|---|
| 研究线比较表 | 各研究线的问题、研究对象或测量量、核心假设、主要发现、证据强度、有效范围、未解决问题与论文锚点 |
| 关系与演化说明 | 定义或方法如何被继承、证据如何支持或挑战解释、研究边界如何变化；区分有来源的关系和待验证的综合判断 |
| 研究机会清单 | 缺口对应哪个未解释现象、适用边界或重要决策，已有解释为什么不够，什么观察能区分可能答案，以及最近反方证据 |

时间先后、术语相似和论文并列不能自动成为继承、冲突或因果关系。测量对象不同的结果不能直接写成矛盾。没有找到争议时，明确其缺失，仍可从重要的未测量现象或证据适用边界寻找问题；不为填表编造冲突。

图中的节点和连线必须能回到表格中的判断及来源。表格承载完整含义，图负责帮助阅读；图渲染失败不影响核心信息。每个进入候选池的机会使用稳定编号，便于追溯到 map，避免另建多套重复证据档案。

BAC 案例可作为综合练习：把来源记录、信息贡献、团队收益和干预效果按研究对象与假设比较，再检查它们的差异是否产生可研究的实际问题。不能仅把“这些指标不同”改写为一个已认证的新方向。

对用户的直接改善是：能够顺着 map 理解题目怎样产生，也能看出哪些方向尚缺材料，而不仅看到论文简介。

### 在昂贵查新前筛掉平凡候选，并允许重新探索

将初始候选生成与正式保留数量分开。可继续探索通常的 3–7 个初始候选，但不得为了数量硬凑最终方案；正式保留可以只有一个，也可能为零。

候选说明在现有科学问题、假设、预测与反证基础上，合并补足以下判断，避免重复扩成大量字段：

- **为什么重要：** 回答后增加什么知识、排除什么解释或改变什么决策；只写“提高准确率”“具有应用价值”不够。
- **为什么尚不平凡：** 常规解释或简单办法预期能做到什么，仍有哪些由证据支持的未知；不强制寻找反直觉结论。
- **差异为什么重要：** 相对最近工作，新对象或新条件会检验什么重要的适用边界，而不只是构成一个未出现过的实验组合。
- **怎样区分可能答案：** 给出能区分候选解释、揭示规律或确认实际增量的观察，不只写“方法效果更好”。
- **最强替代方向：** 同样投入可以研究什么，保留本候选的理由，以及会推翻优先级的条件。

定性判定分为保留、实质重构、作为工程事项处理、淘汰。以下情况优先重构或淘汰：假设基本由定义保证；收益只是更多信息或更多预算且未提出额外问题；方法名称掩盖了尚不存在的机制；场景迁移无法说明重要边界；成功与失败都无法产生有意义的结论。

简单方法获胜不等于研究没有价值。如果研究能可靠发现重要失效范围、修正已有认识或改变采集与干预决策，仍可成立。负结果和复现同样需要重要问题与充分证据，不能自动承诺论文价值。

生成者共享事实材料和 map，但首轮不提供预定最佳候选或优先级。按问题特点选择不同探索角度，例如未解释现象、测量假设、机制边界或资源决策；不强制每个领域套用同一组角色。综合时检查候选是否在研究对象、解释或预期贡献上实质不同，保留不同意见与淘汰理由。

全部候选不合格时，先判断失败来自候选构造还是 map 本身不足，再进行一次有明确新证据或新解释视角的重新探索。不能把改名当作重新生成。仍不合格时交付原因与最有价值的补证据动作，禁止无限重试。用户明确给出探索预算时，以该预算为边界。

### 查新同时判断等价研究与实质增量

把低成本价值筛选放在完整查新之前；通过筛选、拟作为研究方向保留的候选继续使用现有 Premium 查新。未查新的探索方向明确标记，不按完整研究候选推荐。涉及实质问题或假设变化的改写仍需重新查新。

查新采用两个层次：先核对问题、解释或预测是否已被等价回答，再核对拟增加的条件为什么可能改变已有结论。优先比较最接近、最可能否定新意的工作，辅以同义问题、相邻方法及适用边界检索。旧方法已经能回答问题时，不能只凭协议组合更齐全主张创新。

每个拟保留候选附一份简短的最近工作比较：共同问题、已有答案、剩余未知、差异的科学意义和仍未确认的等价性。直接近邻全文无法取得时保留未定结论；不能用检索数量、Premium 字样或“未搜到”替代新颖性判断。

同时检查综述依赖的实际交付成本。优先复用本轮已完成的精读与来源定位，减少重复解释；完整查新尚未完成时如实报告，不把本计划视为允许降低现有证据标准或擅自实现新的轻量综述档位。

### 让各轮审查承担不同判断任务

第一阶段保留现有默认轮数和人数，先改变审查内容，避免同时修改调度协议。每轮内部仍独立读取证据，汇总以论证和反例为依据，不以多数票替代判断。

| 轮次 | 主任务 | 本轮必须新增的判断 |
|---|---|---|
| 第一轮：挑战选题价值 | 即使实验完全成功，这个题目是否值得做；什么替代问题更好 | 价值否决、平凡解释、最强替代方向及其证据 |
| 第二轮：检查解释与辨别能力 | 假设是否由定义保证，预测是否真能区分答案，最近工作或简单基线是否已足够 | 关键反例、方法与证据缺口、必要的实质重构 |
| 第三轮：重新选择与迁移检查 | 在最强备选面前重新判断优先级，检查结论能否超出特制案例 | 选择敏感性、外推边界、最终保留或淘汰理由 |

后续审查保留上一轮事实修正，但不要求接受上一轮的推荐。草稿没有变化可以是合理结果，不过审查应证明完成了本轮不同的问题；纯粹确认字节一致不构成新的科学审查贡献。

每轮只记录新增发现、对候选的影响及尚存分歧。若需要新文献、实质改写或重新生成候选，回到相应业务步骤，不靠添加免责声明消化缺陷。

先用对照评估判断不同轮次是否有增益；自适应减少轮数属于后续优化，不能在现有运行约定不支持时假装已执行必需轮次。

### 让报告反映真实结论，减少实验细节对主线的挤占

开头用一页以内的篇幅说明：研究问题、为什么值得做、关键证据链、与最近工作的差异、推荐依据及当前确定程度。然后呈现 map、候选比较、查新边界和最小判别动作。

把三种业务结论明确区分，并同步到配置、报告检查及现有完成判据，不能仅修改标题：

| 结论 | 适用条件 | 交付要求 |
|---|---|---|
| 有可推荐候选 | 价值论证成立，拟推荐候选完成所需查新与独立审查 | 给出科学价值与近期投入两种排序；数量不限于初始候选数 |
| 当前范围内无合格候选 | 已有证据足以支持当前候选的淘汰，完成约定的探索与必要复核 | 交付淘汰理由、范围与重新开启条件；不声称全领域没有好题目 |
| 证据不足，暂不能推荐 | 关键文献、输入或必要执行尚未完成 | 只交付明确标识的阶段性评估，说明缺口和恢复位置；不得认证新颖性或全流程完成 |

无合格候选可以是有效的评估结论，但不能成为跳过必要工作的捷径。证据不足不能被重命名为“已评估但没有好题目”。具体实现必须使业务结论与现有运行状态一致，避免结构检查通过而语义仍要求强选最佳候选。

最小下一步只说明要排除哪个关键未知、最省投入的观察是什么、什么结果改变去留。不默认展开完整统计方案、平台建设和产品路线；这些内容在题目成立后交给 `research-plan`。

## 实施范围与顺序

按四步推进，每步有可审阅产物；本轮不执行这些修改。

| 顺序 | 主要工作 | 完成标志 |
|---|---|---|
| 先固定行为和样例 | 明确价值判断、map 内容、候选去留及三种业务结论，准备少量正反例 | 用 BAC 和一个非软件领域例子能解释同一套规则，且没有预设推荐答案 |
| 改写科研工作流 | 更新主流程及按需阅读的参考文档，重构候选说明、查新比较和三轮审查职责 | 每个候选可追溯到 map；每轮有不同判断任务；没有价值时能够停止推荐 |
| 对齐输出与验证 | 修复标题解析，按业务结论校验报告，同步配置、初始化生成内容及现有运行说明 | 新旧正常报告可读；未完成与无合格候选不混淆；原有证据绑定与恢复保护不退化 |
| 用对照结果决定是否收敛 | 完成结构回归和真实输出比较，根据失败样例精简或修正，再更新文档与版本记录 | 有可复核的质量变化及成本记录；没有提升时明确保留问题，不宣布优化成功 |

预计主要修改范围为 `SKILL.md`、`config.yaml`、`README.md`、`CHANGELOG.md`、现有报告模板、查新指南、审查参考、报告解析脚本及必要的初始化生成逻辑。可增加一份紧凑的研究综合指南承载 map 与价值筛选示例；优先合并重复解释，不按每个判断新建文档或 Skill。

现有阶段证据检查与运行说明只做目标行为所需的一致性同步，不新增 Kernel 功能、Pack 或状态图。根 README、Skill 总览与安装说明仅在能力摘要或接口确实变化时同步。Skill 版本在实施完成后依据兼容性确定，以 `config.yaml` 为唯一来源；本计划不预先宣布新版本。

旧运行与旧报告保留原有含义，不修改历史事件、不把新规则下的判断追认到旧结果。若新旧输出结论无法兼容，应显式标注适用版本并说明迁移方式，不能让旧脚本把未完成报告误读为完成。

## 如何确认完成

### 先验证确定性行为

自动化检查负责可客观判断的结构与一致性：

- 正确识别既有“候选 1”及 C1/C2/C3 标题；拒绝只有标题、缺少实质字段的空候选。
- 初始探索数量与正式保留数量分开；一个合格候选合法，零个候选需要对应结论和理由，不能伪造推荐。
- 查新未完成可被明确表示，且不会因出现 Premium 字样、通过格式检查或附加免责声明而认证完成。
- 检查候选、map 机会编号和引用是否可定位；不能以链接存在证明推理正确。
- 保留证据内容变化、错绑、缺证据及恢复流程的现有保护；按实际变更范围执行回归。

本次文件盘点在 `tests/research-idea/` 仅找到历史缓存，未找到 `.py` 测试源码。实施前须重新确认测试真实位置；若仍缺失，补齐上述最小回归，不能沿用旧计划中的通过数量充当本次结果。测试源码放仓库 `tests/research-idea/`，运行产物放届时任务工作区。

### 再比较科研输出质量

使用实施前版本与修改后版本做成对比较。先固定可公开的资料、允许读取的证据、模型配置、预算和任务目标，并记录 Skill 与依赖版本；初轮用相同文献材料隔离科研综合的影响，随后至少选一个案例验证真实检索到交付的整条链路。输入不包含旧报告、预定最佳方向或本次批评结论，避免只学会迎合诊断。

| 样例 | 主要检查什么 |
|---|---|
| 脱敏 BAC 项目背景与论文材料 | 能否分开价值与资产适配，建立实质 map，比较替代方向；不要求必须淘汰 C1 或改选 C2 |
| 非软件领域的实验现象与相互不完全一致的研究 | 能否区分测量差异和真实矛盾，提出有依据的解释与判别预测 |
| 资料充分、已有研究高度覆盖的主题 | 能否识别平凡差异、保留重要复现的可能性，并在必要时给出无合格候选 |
| 关键文献受限或输入不足 | 能否保留证据不足结论，不通过补写宏大主张或大量免责声明完成推荐 |

初轮每种样例运行一对新旧版本，仅用于发现问题。对支撑“质量提升”结论的 BAC 和非软件样例，各补足至少三对独立运行，观察方向是否稳定；该规模只提供初步证据，不作统计显著性或跨领域普遍有效的承诺。

隐藏版本标签并随机排列结果，由用户或领域评阅者比较以下内容，给出偏好、持平或无法判断及具体依据：问题重要性、知识增量、map 的解释能力、候选区分度、证据准确性、表达可读性和下一步的决策价值。AI 可辅助定位缺陷，不能由生成者自评分代替领域认可。

验收要求：结构与边界用例通过；没有新增严重证据错误；核心样例在 map 综合或价值论证上呈现可说明的改进，且未以明显损害其他维度换取。结果混合或评阅者分歧较大时，报告为尚未证明整体提升，继续定位原因。篇幅、引用数、字段数、Agent 数量和更高自评分均不作为成功标准。

同时记录耗时、模型用量、补读范围和各轮新增发现。默认人数与查新档位不增加；若质量提升依赖明显更高成本，应单独呈现取舍，不能隐去成本后声称流程更优。

## 风险与待确认事项

- **过度追求惊艳：** 不把反直觉、宏大命名或复杂方法当价值代理；允许重要的小问题、测量研究、复现和负结果。
- **过度淘汰：** 重要性不清楚时区分可补证据与已经平凡，避免把新领域和高风险问题全部淘汰。
- **过拟合 BAC：** 规则使用通用科研概念，不把日志、来源审计或人类干预写成默认研究框架；必须通过非软件案例。
- **流程膨胀：** 每项新增产物都应帮助去留或比较判断；能写在现有表格中的内容不另建文件，重复审查和解释应删除。
- **查新成本与外部限制：** 在不改变现有依赖标准的前提下复用证据；依赖不能完成时交付有限结论，不在本次悄悄扩展其他 Skill。
- **现有工作尚未提交：** 当前目录已有相关修改，实施前需保存可核对基线并确认实际文件状态，不覆盖已有工作，不以版本号相同推断内容相同。

实施时真正需要结合案例确认的是目标研究贡献、关键资源和可接受预算；这些是正常输入，不是现在制定计划的阻碍。真实比较尚未运行，本文不宣称优化效果已经得到验证。
