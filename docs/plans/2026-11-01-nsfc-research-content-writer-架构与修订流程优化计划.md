# nsfc-research-content-writer 架构与修订流程优化计划

本计划供维护者审查。方案参考 `nsfc-justification-writer` 当前的职责分层与修订流程，结合研究内容、特色与创新、年度计划之间的依赖关系设计。本轮仅编写计划和项目记录；以下功能均为拟实施内容。

## 这次要改善什么

研究内容、创新点和年度计划，其实是在回答同一个项目的三个问题：准备做什么、为什么值得这样做、准备怎样完成。三部分文字各自流畅，仍可能出现创新没有实验支撑、任务调整后年度计划未更新的问题。

例如，作者把研究内容中的关键验证从单中心改为多中心，创新点和进度安排就需要重新检查；但如果作者只要求润色一句创新表述，合理的研究方案不应随之被重写。优化后，Skill 应判断任务需要多大改动，检查三个章节的关联，并通过脚本保护文件写入。

**本轮固定保留三条经验边界：3–4 个子目标、三年年度计划、研究内容 12–15 页（含图表）。** 这些是用户确认的有效经验，不因参考架构迁移而取消、放宽或改成需要重新讨论的事项。除非用户另外提出明确要求，后续实现继续以此组织写作。

## 现状与专业判断

当前 Skill 已有值得保留的领域方法：先明确指标、对照和数据来源，再完成研究内容，从研究内容提炼创新，并安排三年里程碑；规划关系留在内部，成稿使用自然叙述。

主要缺口在于执行分工和修订能力。当前规范依赖 AI 直接写文件，附带脚本尚不能形成完整的检查、备份、写入和恢复流程，也未充分区分新写、重构、审查与润色。

| 已核实的现状 | 对使用和维护的影响 |
| --- | --- |
| `SKILL.md` 禁止最终正文残留 `S1/S2` 等内部编号，README 示例和输出检查器却要求这些标记 | 按写作规范完成的稿件可能被检查器误判；AI 可能为通过检查把内部编号写回正文 |
| `validate_skill.py` 要求入口中已经没有的元数据字段，以及当前不存在的 `plans/`、`tests/` 目录 | 旧校验入口不能代表现行规范，也不宜通过补建历史目录来修复 |
| 配置声明禁写范围，尚无统一的提案检查和安全写入入口 | 文件边界主要靠 AI 自觉遵守，缺少可执行保护与明确恢复路径 |
| 主流程默认同时编排三份文件，修改幅度和关联检查范围未细化 | 单章节润色可能扩大为全套改写；实质修改也可能未充分检查关联影响 |
| 固定词表扫描“首次、领先”等表述 | 能提示字面风险，不能判断证据是否支持；也不能替代创新性和科学保真的判断 |

参考 Skill 的成熟经验是“宿主 AI 理解与改写，Python 检查与安全写入”，以及先诊断再选择修订幅度。研究内容写作器应借鉴这些原则，同时补足多文件联动。参考实现仍需逐项核对，例如其 `preview` 默认写入、结构检查按变更行匹配命令等行为，不直接照搬。

## 优化目标与范围

完成后，Skill 应能根据任务选择修改范围，从现有项目材料理解方案，在三条经验边界内完成写作；既检查章节之间的科学关系，也给出可检查、可恢复的文件修改结果。

| 职责 | 拟定归属 |
| --- | --- |
| 科学问题理解、研究任务设计、创新判断、进度合理性、正文修订 | 宿主 AI |
| 写作方法、学科差异、关联复核、典型正反例 | 按需读取的参考资料 |
| 路径、写入白名单、引用 key、结构变更、字数统计、diff、备份与恢复 | Python 脚本 |
| 修改内容、理由、证据缺口及作者决策 | 面向作者的简短交付说明 |

保留现有三个输出角色、默认文件路径，以及 `project_root`、`output_mode=preview/apply` 的使用语义。立项依据和研究基础作为只读上下文，不在本次重构中扩展成其他章节的写作器。

本次实施范围不包含自动文献综述、图表生成、全标书 QC、外部模型 API、系统级安装副本或远程发布。用户未提出 Verifier、State 或 Pack 接入需求，本计划不引入这些组件；本轮未调用 `verifier-state-architect`。备份与文件恢复也不扩展成独立事件账本或通用运行协议。

## 改进方向

### 明确任务类型，控制实际修改幅度

在主流程开头识别任务与目标章节，简短诊断“必须修复、建议优化、可以保留”，重要问题说明位置、依据和影响。合理内容可以保留，不用改动量衡量效果。

| 任务 | 默认行为 |
| --- | --- |
| 新写 | 从材料建立研究任务及验证关系，生成用户要求的章节；全套任务完成三章联动 |
| 重构 | 根据科学逻辑重排内容，解释重要调整，检查创新和年度计划是否受影响 |
| 审查 | 只读诊断和建议，不写入、不创建正文文件 |
| 润色 | 优先局部保真修改，保留成熟结构、研究设计与作者声音 |

任务类型由 AI 判断，不为四种任务分别增加一套 CLI。单章节任务只修改授权章节，同时只读检查关联内容；发现其他章节需要实质修改时，按已有授权决定是否同步，没有授权则列出建议和影响。

交付说明收敛为“研究设计与结构调整、学术表达改进、科学歧义与证据缺口、作者决策事项”四类；没有问题的类别简短注明即可。关联影响归入相应类别，不再另做一份重复报告。写入任务同时附目标文件、实际 diff、备份和恢复方法。

对作者而言，局部需求能得到局部结果，全面重构也有明确的修改理由。

### 从项目材料理解方案，按缺口影响决定是否追问

先读取目标正文、立项依据、研究基础和必要文献，从中提取研究对象、核心问题与假设、总体目标、任务、实验或数据来源、资源及进度约束。现有信息表不再作为使用前必须填写的入口，其有效内容并入研究设计参考资料。

缺口分两类处理：不影响现有内容保真修订的，登记后继续；影响实验可行性、科学解释或项目承诺的，停止依赖该信息的改写，提出集中问题或候选方案。不得补造样本量、可用队列、合作条件、伦理进度或预期提升幅度。修订时保留待决内容，新写时明确哪些部分仍是建议、尚不能定稿。

对作者而言，已有材料可以直接用于工作，补充信息只针对真正影响方案的缺口。

### 保留经验边界，补强研究设计的推断能力

继续围绕 3–4 个子目标规划。每个目标保留“指标或可判定结果、对照、数据或验证来源”三项基础要求，并根据问题补充以下关系：这一任务回答哪个未知，什么结果支持或削弱假设，对照能排除什么替代解释，任务如何依赖前序结果，失败时有什么有依据的备选路径。

这些内容形成内部研究设计关系表，服务于构思和复核，不强制全部写成正文表格，不以 `S1–S4` 编号替代叙述。润色任务不会因为原文未显式列出三件套而自动扩写整章；数量不符合经验边界或关键设计缺失时，给出诊断并按任务授权处理，不为凑数编造任务。

验证方法按学科选择：机制研究关注干预、救援和竞争解释；理论与方法学研究关注成立条件、可识别性、证明或反例，以及必要的模拟验证；应用研究关注基线、公平比较和真实场景表现。对照可以是适合问题的理论基准或竞争解释，不将所有课题改成机器学习实验。

**三年计划和 12–15 页继续保留。** 三年里程碑按依赖关系安排；篇幅按实际章节内容和排版规划。脚本可报告字数，不把固定字数换算成实际页数；没有编译结果时明确“尚未核验实际页数”。保留原有字数建议作为辅助参考，不新增强制凑字检查，也不沿用“加入大量图表通常不影响文字篇幅”作为普遍承诺。确需验证排版时使用项目官方构建 wrapper。

对作者而言，经验边界继续提供稳定的写作尺度，复核重点进一步落在研究能否回答问题上。

### 将三章节关联检查纳入每次实质修订

研究内容是研究任务的主要依据，创新点说明其中的实质增量，年度计划说明任务如何推进。对三个方向分别复核：

- 创新点能否回溯到具体研究设计和验证，是否夸大尚未建立的能力；
- 年度里程碑是否覆盖全部子目标，顺序是否符合数据、实验和资源依赖，每年是否有明确交付；
- 三章是否与立项依据的科学问题和研究基础中的实际条件一致。

保留创新点 1–3 条、少而精的原则。回溯关系通过自然语言说明，不要求正文包含固定标记。关联关系本身由 AI 判断，Python 不通过关键词数量或编号匹配宣称一致性已通过。

增加队列、改变主要终点、调整样本量、替换关键实验或改变核心机制，都可能改变项目承诺。依据充分且属于已有授权时可执行并解释；否则给出选项与影响，保留待决原文，完成其余可保真修改。已有授权不重复询问，纯语言调整不逐项确认。

对作者而言，每次重要修改的连带影响可见，也能保持对研究设计的实际控制。

### 建立适合三份正文的安全写入流程

拟新增统一 Python 入口，接收 AI 已完成语义复核的正文提案。继续保留 `preview` 只读、`apply` 写入的直观含义，默认模式沿用现有 `apply`；仅审查任务不进入写入流程。提案按既有三种文件角色显式绑定，不照搬立项依据的单文件自动发现机制，也不静默扩大白名单。

脚本在写入前检查规范化路径、项目范围、禁写文件、引用 key 及结构变化，输出每个目标的 unified diff（逐行展示原稿与提案的差异）。缺失引用保留待核验项，不为通过检查删除必要引用或改换科学主张。`\subsection` 等已有标题与层级继续受保护；结构检查应区分文字修改与结构改变，避免同一行标题后的正文变化也被一律拒绝。

三文件写入采用“本次全部检查完成后再开始修改”的方式：

1. 确定本次获授权、实际变化的文件集合，只读记录原文件状态；缺失必需目标时沿用模板准备提示，不自动初始化项目。
2. 对整个集合完成检查和差异预览；任一文件失败，全部保留原样。
3. 写入前备份全部会变化的原文件，备份失败则不开始替换；再次确认原文件未被其他操作修改。
4. 分文件执行安全替换；遇到可捕获的中途错误，恢复本次已替换文件并返回失败。进程中断或恢复异常时，保留备份与明确的恢复指引，不宣称三文件整体原子成功。
5. 提供按本次文件集合查看差异和恢复的入口；恢复前保护当前版本，发现额外修改时停止覆盖并说明冲突。

无内容差异时不执行替换。`main.tex`、`extraTex/@config.tex`、`.cls/.sty` 始终处于禁写范围。目标选择、提案读取与备份恢复都验证路径；从其他工作目录和独立安装副本运行时仍能定位自身资源，不依赖相邻 Skill 的源码。

对作者而言，可以预览改动、查看实际写入结果，并在失败或撤销时找到可靠的原稿。

### 精简文档组织，修复旧入口并保持迁移清楚

`SKILL.md` 按现行上游规范组织为“目标—流程—约束”，承接输入、执行、输出、输出管理、校验和失败恢复。触发描述覆盖研究内容及关联章节的新写、重构、审查、润色，具体参数和路径放正文或配置。

参考资料拟收敛为研究设计与分节写法、质量控制、回归案例、篇幅指导四个主题。整合现有信息表、三件套、创新坐标、年度模板、术语表和反模式资料中的有效内容；先建立旧规则到新位置的映射，再决定合并哪些文件，避免只压缩目录却丢失领域规则。README 解释调用方法和模式，不复制整份执行规范。

脚本只按已实现的职责拆分必要模块，不复制参考 Skill 的整个 `core/`，不新增通用科研写作框架，也不引入对兄弟 Skill 目录的动态导入。复用前核对真实接口；通用事件、证据、Gate 等能力如以后确有需求，沿用 BSK，领域 Skill 不另建平行协议。本次只建设正文文件操作所需能力。

旧 `check_project_outputs.py` 与 `run_checks.py` 公开命令和参数优先通过薄包装保留，转向新的确定性检查；文档明确已移除“正文必须出现 S 编号”的旧判断。`validate_skill.py` 改为真实有效的局部配置、资源和引用检查，不要求冗余版本字段或历史计划目录。`create_test_session.py` 不再向 Skill 源目录写计划与测试产物；保留入口时显式使用已声明的任务目录。模板与其他资源经引用核对后处置，不删除用户历史产物。

配置中的旧 `checks.subgoal_markers_min` 在迁移中明确停用，兼容读取时提示已不参与判定；经验性子目标数量与三年、页数规则由单一配置来源表达并同步文档。版本仅维护于 `config.yaml:skill_info.version`；本轮不改版本，实施时根据最终兼容性确定版本增量。

对作者而言，现有调用方式可以继续理解和使用，新流程不再被相互矛盾的旧说明干扰。

| 3. 实现确定性保护 | 建立统一入口、提案检查、只读预览、集合检查、备份、写入与恢复；修复旧包装入口 | 可在隔离项目中运行的最小安全链路 |
| 4. 定向验收与同步 | 验证失败路径和兼容命令，完成典型写作案例对照，核对文档、配置与独立安装可用性 | 验证摘要、剩余限制、README、Skill 与仓库变更记录、BAC |

原则上只读参考 Skill、BSK 和公共 LaTeX 包；发现复用必须修改共享层时，先说明收益、接口影响与新增验证范围，不把共享重构隐含在目标 Skill 的实现里。正式计划放 `docs/plans/`，任务中间材料遵循一个任务根目录；不创建 Skill 内部 `plans/`、运行缓存或测试产物目录。

## 如何确认完成

### 写作与修订案例

语义案例同时检查正文和作者说明，不用固定词语、编号计数或机械分数替代科学判断。

| 场景 | 应观察到的结果 |
| --- | --- |
| 材料充分，新写三份正文 | 3–4 个子目标有判定依据，创新有任务支持，三年安排体现依赖；正文无内部规划编号，按 12–15 页规划 |
| 成熟稿仅要求润色创新点 | 保留合理研究设计和其他文件，改动集中且有依据 |
| 研究内容调整了关键验证来源 | 识别创新和年度安排的相关影响，按授权同步或给出明确建议 |
| 材料缺少样本量、外部队列或合作条件 | 不补造承诺；完成有依据部分，明确待决内容与成稿限制 |
| 作者只要求语言润色，原设计存在机制或终点争议 | 不暗换机制、终点或验证方案；给出证据与选项 |
| 机制研究与理论方法学研究各一例 | 对照、判定结果和失败解释符合学科，不统一套用机器学习验证菜单 |
| 用户仅要求审查 | 给出诊断和建议，正文文件不创建、不改动 |
| 没有实际编译结果 | 明确区分篇幅规划与实际页数验证，不宣称已满足排版页数 |

至少选择“完整三章新写、成熟稿局部润色、研究任务变化后的关联处理”三个案例，用旧版与修订版处理同一输入，保留结果并评阅改善和退步。旧版确定性检查存在已知冲突，作为基线局限记录，不以其能否通过作为科学质量标准。本轮只规定验收案例，不运行生成评测。

### 确定性检查

| 检查对象 | 必须验证的行为 |
| --- | --- |
| 正常与无差异提案 | 只写获授权目标；无变化不替换文件；禁止修改模板和配置 |
| 预览与审查 | `preview` 不写正式正文；仅审查不调用写入入口 |
| 路径边界 | 越界路径、符号链接逃逸、禁写目标与不属于本次集合的文件被拒绝 |
| 引用与结构 | 缺失 bibkey 或未经授权的标题、结构变化阻止写入；合法正文改动不因同行存在标题而误拒 |

## 风险与审查重点

最需要审查的是两个行为边界：一是单章节修改时，是否接受“只读检查关联章节，按已有授权修改”的范围控制；二是三文件修改采用全量预检查和失败恢复，明确不承诺文件系统层面的整体原子替换。

技术上要避免把研究设计关系表再次做成强制填表，或让安全检查过严而阻碍合法正文修改。多个必要的实验条件应留在正文；只用于作者审查的缺口和决策说明另列，避免正文被流程标签和重复免责声明挤占。

参考架构的收益最终需要由实际行为证明。计划审查通过后再实施，本轮不修改目标 Skill，也不把计划中的能力表述为已经具备。
