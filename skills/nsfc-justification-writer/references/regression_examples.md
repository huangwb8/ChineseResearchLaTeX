# 边界表达回归样例

这些案例用于人工复核写作规则，不是固定短语测试，也不要求 Python 统计否定词。每个案例都应同时检查正文和独立审查记录：正文先陈述科学判断，审查记录保留证据风险与待核验项。

## 触发边界示例

| 请求 | 是否适用 |
| --- | --- |
| “润色这份国自然立项依据，保留成熟结构” | 是，局部保真修订。 |
| “审查基金立项依据，指出证据和推理问题” | 是，只读诊断与建议。 |
| “按现有材料重构立项依据的现状与假设” | 是，说明重要重排依据。 |
| “写研究目标和技术路线” | 否，交由研究内容写作能力。 |
| “补齐 bibtex、核对 DOI” | 否，单独的文献条目任务交由文献管理能力。 |
| “优化 nsfc-justification-writer 的 SKILL.md” | 属于 Skill 维护；本 Skill 是修改对象，不应据此执行申请书写作。 |

## 1. 研究意义：对象价值与外推边界

- **输入要点**：材料支持某现象与疾病负担相关；前期结果来自单中心；尚无临床获益证据。
- **正文应呈现**：先说明该现象为何值得研究，再保留“现有证据来自单中心”这一会改变解释的范围限定。
- **审查记录**：证据等级、跨中心外推风险、临床获益待核验。
- **避免**：把“本项目不负责临床决策、不能证明获益、仍需外部验证”连续写成研究意义主体。

## 2. 研究现状：路线限制合并

- **输入要点**：路线 A 解释了机制 M 但依赖条件 C；路线 B 提供了跨平台结果但无法区分机制 M 与替代解释。
- **正文应呈现**：按“已有认识—具体限制—当前缺口”综合两条路线，合并重复限定，保留所有影响解释的必要条件。
- **审查记录**：各路线证据类型、对照不足、替代解释和需补充的文献。
- **避免**：每篇文献后重复追加“不能证明因果、不能推广、不负责临床”的责任切割。

## 3. 科学假设：表征稳定性与临床获益

- **输入要点**：假设预测某表征在不同平台上保持稳定；项目没有治疗干预或临床终点。
- **正文应呈现**：明确可证伪的稳定性预测，并用一条承接句说明稳定性不等于临床获益。
- **审查记录**：终点层级差异、临床外推边界、未设计的下游验证。
- **避免**：把表征稳定性、临床阈值和治疗获益统称为“临床价值”，或连续罗列所有未验证任务。

## 4. 证据不足：核对主张与授权

- **输入要点**：只有相关性结果，缺少机制实验和外部队列。
- **正文应呈现**：新写使用与材料匹配的措辞。原稿含因果主张时，依据明确且在授权范围内才改为相关性观察；材料不足或无相关授权时保留待决段落，完成其他保真修订。
- **审查记录**：缺失证据、待核验文献、需要独立验证的关系。
- **避免**：用“不能证明、不能排除、仍需验证”堆叠句子掩盖材料不足，或补造机制结论。

## 5. 科学问题与假设：从缺口自然收束

- **输入要点**：现有研究能在生成队列中复现样本关系，但尚不清楚队列构成和观测平台改变后，这些关系是否仍代表同一生物学状态；项目提出关系型表征作为切入点。
- **正文应呈现**：先解释“生成队列内可复现”为什么不足，再提出“哪些关系具有跨队列可重复性、在什么条件下能够外推”的核心问题，随后说明关系型表征若承载更稳定的生物学信息，应在独立队列中保持与生物学参照一致的结构。
- **审查记录**：外部队列、参照面板、模型容量和评价指标作为验证条件记录，必要时说明哪些结果会推翻该解释。
- **避免**：把问题写成 `R1/R2/R3` 验证任务，把假设写成 `H1/H2` 加模型、折叠、调参和敏感性分析清单；也不要把“本项目依次检验……”作为科学问题的主体。

## 成熟稿润色与合理结构

- **输入要点**：稿件已有“问题缘起、已有认识与未知、研究价值”等标题，论证完整；仅请求润色。
- **正文应呈现**：保留标题、合理段落、作者声音，局部改善重复和指代，不凑成固定四节。
- **交付说明**：分清必须修复、建议优化、可以保留，重要调整说明依据；可明确结构合理，予以保留。
- **避免**：为达到段数或比例预算大幅重写，或用改动量代替修订理由。

## 未评价与不能泛化

- **输入要点**：所读材料只说明跨平台表现尚未评价，无理论不可能性结论。
- **正文应呈现**：承认同平台研究的贡献，把跨平台表现界定为证据空缺。
- **交付说明**：记录读取范围和待补评价，不声称领域研究已穷尽。
- **避免**：改成“现有方法无法跨平台泛化”“首次填补空白”，或把特定条件的不可能性推为普遍结论。

## 假设依据与前期材料分工

- **输入要点**：支持假设的探索观察仅在文末出现，另有模拟平台基础和外部文献结果。
- **正文应呈现**：关键观察前置或紧邻假设，保留探索性质与来源；平台只作可行性衔接，小结回收要点。
- **交付说明**：解释前置如何使推导可理解，不把文献结果写成团队成果。
- **避免**：无前期结果时虚构观察或强加“前期基础”段；把有平台当作机制成立的证据。

## 未授权的因果变化

- **输入要点**：原稿“P 导致疾病进展”，仅提供横断面相关性结果，作者只要求语言润色，可能另有未提供的因果证据。
- **正文应呈现**：待决段落保留原文，其他措辞可保真修订。
- **交付说明**：指出依据不足，列“补充因果证据”与“将主张调整为相关关系”的选项及影响，明确尚未采用；全文仍有待决段落。
- **避免**：自动改成“P 与进展相关”并称全文定稿。若作者已授权依据明确的证据强度纠错，可执行并解释，无需再问。

## 两项必要条件

- **输入要点**：结论同时依赖可识别性和噪声矩有限两个必要条件。
- **正文应呈现**：两项均保留，拆句或分段改善可读性。
- **交付说明**：解释两个条件分别如何影响结论。
- **避免**：为满足“每段一个限定”删去或移走任一条件。

## 方法学课题与受保护内容

- **输入要点**：项目研究未知算子下的可识别性和误差界；句段需移动，含公式、数值、标签及引用。
- **正文应呈现**：保持理论问题和假设，保留所有必要数学条件；公式、数值和引用随其主张保真迁移，标签保持定位含义。
- **交付说明**：区分性能与科学贡献，分别记录 bibkey、元数据和具体主张支持性的实际核验层次。
- **避免**：强加生物机制、改成性能口号，或将 bibkey 存在、编译通过说成文献支持性已核验。

## 仅审查的任务

- **输入要点**：用户只要求审查，正文存在研究缺口表述过强的问题。
- **正文应呈现**：不修改、不创建正文；若作者需候选 diff，仅显式 `--dry-run`。
- **交付说明**：给诊断分级与建议，按四类说明组织，作者决策列选项与当前状态。
- **避免**：因为主流程默认自动写入而调用未带 `--dry-run` 的 preview，或恢复旧 review/coach CLI。
